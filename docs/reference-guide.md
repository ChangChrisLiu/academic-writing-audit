# 文献核验与引用指南

[指南索引](README.md) · [中文说明](../README.zh-CN.md) · [Home](../README.md)

这组 skills 把文献是否存在、书目信息是否准确、引用是否对应，以及文献是否支持正文观点分开检查。先确定问题属于哪一层，再选择相应入口。

| 任务 | Skill | 完成依据 |
| --- | --- | --- |
| 核实文献真实性 | [reference-authenticity-audit](../skills/reference-authenticity-audit/SKILL.md) | 两个独立 agent 的 Scholar 优先检索记录及完整字段核对 |
| 校对与整理 LaTeX 文献 | [latex-bibliography-audit](../skills/latex-bibliography-audit/SKILL.md) | 目标版本原始 BibTeX 导出、论文身份判断和引用键映射 |
| 检查 Word 引用 | [word-citation-audit](../skills/word-citation-audit/SKILL.md) | 格式依据、正文引用清单和文末条目的双向对应 |

## 文献检索使用无痕模式

所有执行在线文献检索、出版记录核对和 Cite → BibTeX 导出的 agent，都必须使用已确认的 **Incognito / Private 无痕窗口**。先从浏览器实际标识或工具明确返回的模式信息确认，再开始访问。普通新标签页、命名会话、新建 profile 或没有显示登录账号都不足以证明无痕模式。每位 agent 各自保留模式依据、检索记录和时间。

不使用用户已经登录的普通浏览器会话，不为该流程登录用户账号。工具无法创建、控制或确认无痕窗口时，停止在线检索，明确记录未完成的要求，继续可以执行的本地核对。不能静默改用普通窗口或模式不明的检索工具。无痕模式本身也不证明文献真实或两位 agent 的判断独立。

## 两个 agent 独立核实真实性

先建立一份可复用的文献清单，保存原始条目、正文位置、目标版本、疑似重复组和来源记录。疑似重复只做分组，核实前不合并。两个 agent 收到同一组原始文献和中性索引，各自先去 Google Scholar 检索，不预先共享判断。每位 agent 都核对完整标题、完整作者及顺序、具体发表年份和刊物，并确认所指版本。不能把一半文献分给一个 agent、另一半分给另一个，就称为交叉验证。

标题中的实质词语、作者、年份和刊物必须一致。大小写、排版转义和有依据的标准缩写可以记录为形式差异；缺少副标题、作者顺序不同或会议版与期刊版混淆需要查证。截断的检索摘要不能证明完整字段一致。

即使 Scholar 元数据看起来完整，两位 agent 也都要各自核对目标版本的出版社、正式会议记录或论文原文等原始出版信息。两人可以找到同一处可靠来源，但不能把这种情况描述成两个互不相关的底层来源。保留能复查的最小书目信息摘录、导出文本或截图，公开记录去除账号信息和会话参数。

两份独立记录完成后再逐项比对。有分歧时回到论文、出版社或正式会议记录，不按票数决定。某个检索工具打不开 Scholar 时，先区分工具读取问题与网站实际限制。只使用已确认的无痕浏览器入口，无法确认或控制该模式时保留未完成状态。遇到访问挑战或可用无痕入口也失败后停止，不循环尝试端点。Scholar 检索受阻、缺少第二位 agent 或信息不足时，继续给出已取得的证据，但保留未完成状态。Scholar 的覆盖与自动提取存在限制，未命中不等于论文不存在。[Google Scholar 官方说明](https://scholar.google.com/intl/en/scholar/help.html)

```text
使用 $reference-authenticity-audit 核验这些参考文献。
让两个独立 agent 各自在已确认的无痕窗口中从 Google Scholar 检索同一组原始条目，
核对完整标题、作者及顺序、发表年份、刊物与版本。
两边完成后交叉比较，保留来源和分歧。先审查，不改原稿。
不能访问或尚未核实的部分请明确标出。
```

## 每条 BibTeX 均须取自 Google Scholar

逐条打开目标论文和版本的 Google Scholar 搜索结果，点击 **Cite → BibTeX**，保存实际显示的完整导出、检索位置、取得日期和文件摘要值。已有可追溯且确认了无痕模式的原始导出可以按版本复用，并保留原采集日期。把导出的题名、完整作者及顺序、年份和刊物与两位独立核验者的记录及原始出版来源再次比对。[Google Scholar 官方导出说明](https://scholar.google.com/intl/en/scholar/help.html)

**正式 BibTeX 必须由 Google Scholar 的 Cite → BibTeX 实际导出提供。** `.bib` 保留条目类型、引用键及各字段，下面的标题符号修正是唯一文本例外。原导出缺少 DOI 时，出版社提供的 DOI 只进入核验记录。即使元数据齐全，agent 也不能自行拼写条目。已有条目同样要逐条与真实导出对照。拿不到导出、版本有歧义或出版社与 Scholar 有实质冲突时，保留现有文件，把这条标为待处理，不为新引用生成占位 BibTeX。

对于 `pi0.5` 这类被简化成普通文字的符号名称，可以根据目标论文的实际标题恢复希腊字母、上下标或其他数学符号，使用正确的 LaTeX 或 Word 表示。不能仅凭字符串猜测上下标形式，也不能把普通词语、缩写或专业术语全局替换成符号。标题的词义、数字和版本保持一致，作者、年份、刊物、引用键等其他字段不变。

保存未经修改的 Scholar 导出，另记标题修改前后文本、原题依据和理由。报告时把“标题符号规范化已核验”与“逐字一致”分开。当前比对脚本会对这种修改返回差异，agent 应核对差异确实只包含已记录的标题符号变化，并确认其他字节一致，不能改写原始导出来获得通过结果。涉及编译或排版时，再检查实际显示。

确认是同一版本的重复项，备份后保留一份实际导出，并把正文、附录、图注和自定义命令中的旧键映射到 Scholar 原键。两个不同作品导出了相同引用键时，保留两份原始证据并暂停修改。按条分别报告导出来源、文献身份和工作条目是否完全匹配。LaTeX 编译、排版和引文是否支持正文主张各自记录。

```text
请在已确认的无痕模式下逐条核对该项目的 BibTeX，并保留模式依据。
每条以对应版本的 Google Scholar Cite → BibTeX 实际导出为准。
仅允许根据原题修正标题符号表示，保留原始导出和修改记录，其他字段及引用键不变。列出缺少导出、工作条目有差异或版本冲突的引用。
先给旧键到导出键的映射。分别报告双 agent 真实性核验、条目原文比对及实际编译结果。
```

## Word 先确定规范，再双向匹配

先读取期刊或作者要求，并核对 Word 或引用管理器当前设置。只看到作者和年份不能直接判定为 APA；只看到上标数字也不能直接判定为某一种编号规范。规范不明时仍可检查明确的对应关系，把格式依赖单独保留。

第一遍从正文查文末，定位缺失、歧义、错误目标和编号或年份后缀问题。第二遍从文末查正文，找出没有观察到引用的条目。图注、表格、脚注、文本框和附录都可能包含引用，应按实际检查范围计入。没有完整文档时，只能说“在已检查部分未找到”。明确允许的延伸阅读单列说明。

Zotero、EndNote、Mendeley 和 Word 原生引用域需要通过相应来源或管理器修复，不能手改显示文字后破坏域。刷新后重新核对编号、顺序和年份后缀。只读文本导出不能证明原生 Word 域、修订视图或版面已经通过。

执行修改时，分别记录刷新、保存和重新打开后的核对结果。更新命令返回成功不代表修改已经保存。核对保存副本中的域指令、来源身份和显示对应关系；界面读取文字与实际页面不一致时，先重新读取并交叉检查，不立即修改引用域。已完成的[原生 Word 刷新测试](../evals/word-native-refresh/README.md)保留了操作记录、前后文件和页面截图。

```text
使用 $word-citation-audit 检查这篇 Word 论文。
先确认所需引用规范及当前设置，再双向核对正文和参考文献。
包括图注、表格、脚注和附录，指出未检查的区域。
报告漏列、未观察到引用、歧义与重复条目，保留正常专业术语。
只审查，不修改引用域或接受修订；真实性若未核实请单独说明。
```

## 在多个检查之间复用结果

LaTeX 和 Word 检查复用同一份文献清单。身份和版本未变、证据可追溯、无痕模式已有确认且没有新冲突时，不因引用键改名或格式变化重新安排两次检索。标题、作者、年份、版本等身份信息改变或出现冲突时，只重开受影响的核验。完成状态仍分别记录真实性、字段一致性、格式对应和成品验证。

旧记录若缺少无痕模式依据，保留原始结果与日期，重新进行受影响的检索后才能满足当前流程。既有的逐字比对或编译测试仍保留原结论，不能追认成无痕浏览器实测。导出比对脚本只检查本地条目，不验证浏览器模式或来源获取过程。

如果还要检查正文观点是否得到文献支持，再把具体论断和论文中的证据交给 [claim-evidence-audit](../skills/claim-evidence-audit/SKILL.md)，不把这个结论混入书目信息检查。

## 用实际产物验证流程

测试应保留原始输入、真实导出或可复查的最小来源证据、修改前后映射和执行产物。LaTeX 检查把编译日志与确切源码版本关联，再核对生成的参考文献与受影响引用。Word 分别记录原生引用域、来源关系、实际刷新结果和渲染检查；只读取 XML、只看到缓存文字或使用其他排版引擎渲染，都不能冒充 Word 引用管理器已经刷新。

判断正确、操作成功和最终成品正确是不同的测试结论。无法执行的部分保留明确状态，不通过修改缓存文字制造成功，也不把 agent 的访问自述单独当作执行证据。

## 适用边界

所有入口可以独立安装。普通格式或对应关系检查不冒充真实性核验；真实性核验需要两个独立 agent 和相应来源访问能力。两位 agent 对同一份截图的判断也不等于两次独立来源检索。模拟案例用于检查决策规则，不能作为真实文献已经核验的证据。
