# 自然表达与逻辑审查

[指南索引](README.md) · [中文说明](../README.zh-CN.md) · [Home](../README.md)

“去 AI 味”在这里指改善可观察的写作问题，包括空洞铺垫、套话、句式缠绕、指代不清、推理跳步和重复解释。某个词或标点不能证明文字由谁撰写，也不把检测分数当作写作质量。

[academic-prose-editing](../skills/academic-prose-editing/SKILL.md) 可以独立处理这类问题。[academic-writing-audit](../skills/academic-writing-audit/SKILL.md) 将这些检查纳入完整学术审查。[scientific-story-audit](../skills/scientific-story-audit/SKILL.md) 重点检查跨句、跨段以及整篇研究主线的连接。只检查一个段落时，不推断全文都已经通过审查。

## 让读者看见论证如何展开

“读起来不像人写的”有时并不是用词错误，而是每句都在陈述正确事实，却没有把这些事实组织成判断。读者看不到为什么需要下一步、作者为什么作出这个选择，以及证据如何支持或限制结论。审查要找出一段结束时，读者比开头多理解了什么。

例如，材料说明相同小时平均温度的样本，超过材料阈值的持续时间可以不同。只写“报告平均温度，报告超阈值时间，两项指标都很重要”，仍然像在罗列。可以写成“小时平均温度相同的样本，超过材料阈值的持续时间仍可能不同。因此，我们在报告小时平均温度的同时，也报告超阈值持续时间。”这说明了第二个指标为什么需要出现，没有补入未经测试的预测优势。

写作中的思考应体现在有依据的取舍、关键区别和解释关系里。为什么一种操作对应当前困难，比较能区分什么，某个结果如何限定解释，都应在必要位置讲清。缺少选择依据时就保留待确认项，不能虚构作者曾经尝试、失败、惊讶或改变想法的经历，也不能把事后能解释的理由冒充真实设计历史。

## 让变化服务于重点

重要的区别需要展开，常规步骤和重复信息可以简写。句子长短、句式和段落篇幅由信息负担决定。简短句可以承载明确发现，较长句可以连接必要条件，但不要求长短交替。每段都采用相同开头、三点说明和总结，也可能压平原本不同的论证任务。

段落之间要有可解释的承接。前一段留下了什么问题，下一段为何接着解释这个对象或判断。连接词只能表达已经存在的关系，不能代替缺失的前提。无需强行给每段加入转折、反驳或戏剧性发现，也不必让每段末尾都重复总结。

有意义的平行结构应当保留，例如对照两个条件对应的定理或实验。专业名词保持稳定，已清晰的作者表达也可以原样保留。随机换同义词、增加插入语、刻意写复杂句或制造不整齐，都不能代替连贯思考。更详细的 agent 规则见[论证展开与表达节奏](../skills/academic-prose-editing/references/reasoning-and-rhythm.md)。

## 连贯段落与标点

生成的学术正文和回复文本默认不用解释性冒号，也不用破折号或两侧留空格的连字符插入补充。可以另起一句，也可以用有实际逻辑关系的从句连接。不要机械地把这些标点全部换成逗号或分号，更不要把段落切成项目符号。

例如，虚构草稿写道“模型具有一个必要条件：两个通道都可用——否则弃权”。可改为“模型要求两个通道均可用，任一通道缺失时均弃权”。后一种表达保留了操作规则，也减少了插入式说明。

术语内部的连字符可以保留，例如 cross-domain 和 follow-up。数学映射 `f: X → Y`、差值 `a - b`、比例 `1:2`、范围 `10–15 °C` 和网址中的符号不属于装饰性句子标点。原文引文、参考文献标题、代码、YAML 以及期刊要求的模板应保持准确。这是库的默认编辑偏好，作者或期刊有明确要求时按其要求处理。

## 先检查推理，再检查流畅度

阅读相邻句子时，确认第二句依据什么从第一句得出。研究对象、样本、终点和条件是否仍然一致，代词能否找到明确的指代，转折或因果连接是否有事实支持。不能因为句子读起来顺畅，就接受未经证据支持的推论。

例如，一个完整系统优于基线，不足以证明其中某个权重规则导致了提高。把“证明”改为“可能说明”仍未补上证据。应回到实际比较，保留观察结果，并把没有被隔离的机制与已经支持的结论分开。

## 通用的概念与语言审查

先根据定义、方法、测量或论证恢复一个表达所指的概念。它表示数据对象、操作、机制、数量、理论性质，还是对证据的解释。再核对范围、条件、单位与结论强度，判断词语是否额外暗示了材料没有支持的机制、因果关系或验证状态。

研究笔记提供的是事实约束，不一定已经是适合发表的措辞。含义明确时，可以把笔记里的直译或简略表达写得自然，同时保护正式专业术语、准确引文和作者已确认的表述。

概念错误与表达生硬要分开处理。词语指错对象、混淆指标或改变性质时，按证据修正概念。概念本身准确但搭配、语法、修饰关系或动作主体不自然时，保留专业术语，修改句子。含义没有定义或专业用法尚未确认时，指出具体缺失，不能猜一个近义词。概念和表述都准确时就保留，不为体现修改量而重写。

专业词是否合适取决于学科、读者和上下文。一个词在其他学科有不同含义，不意味着当前用法有误。领域惯用的隐喻、必要的理论区分以及作者明确定义的新概念都可以保留。对不熟悉但可能规范的术语，应在确有需要且允许时核对可靠的专业来源，不能仅凭陌生感判为错误。定义清楚也不等于已经证明这个构念有效或具有某种作用，这些主张仍需分别核对证据。

替换前比较原词与新词的所指、范围、单位、假设、否定和证据强度。不能把整体变成子集，把条件关联变成因果作用，也不能把一个技术指标换成更熟悉但含义不同的指标。同一概念在同一角色下保持一致命名，相关概念之间的真实区别则要保留。修改涉及当前范围内多个定义、正文或图注时，一起核对，避免全局机械替换。

例如，数据对象实际是 dataset 时，写成 buffer 可能使读者误以为存在缓冲或回放机制。这个问题来自名称与对象不符。真正的输入缓冲区，以及化学或其他领域中有明确含义的 buffer，应按各自语境判断。这个例子不能扩展为禁词规则，代码标识符和原文引文也不能随意修改。

其他常见错误包括将平均绝对误差写成精确率，将百分比变化写成百分点变化，或将数学中的某个性质换成相近但更强的性质。相反，已经准确使用的专业词即使不常见，也不必换成日常词。审查应说明位置、证据、具体问题和最小修复，并明确保留项。完整判断流程与跨学科示例见[概念与语言审查规则](../skills/academic-prose-editing/references/word-choice.md)。

## 审查意见本身也需要准确

实验条件或作者定义的构念可能有简短名称。先读操作定义、表格分组和相邻段落，再判断简称会不会误导。如果实际操作已经解释正确，问题通常是名称需要澄清，不等于研究对象或方法有错。可以保留历史名称并补充操作说明，也可以按需要展开显示名称，不能因此改动实验身份或代码标识。作者明确纠正了对象含义，或名称与实际定义确有冲突时，仍应按证据处理。

审查者的转述也不能补入未经确认的技术性质。例如，材料只说某个分数组合若干输入，不足以认定它是线性加和、概率或因果模型。应保留原文实际给出的操作，把未说明的部分列为未知。即使没有动原稿，一条不准确的审查建议也可能引导后续误改。

## 简化句式时保留科学条件

先找出主语和主要动作，再检查两者之间是否塞入过多限定、并列任务或抽象名词。一个句子同时交代采样条件、分析单位和结果时，通常可以拆开。拆分后，每项条件仍要修饰原来的对象，不能把“仅当两个通道都可用”省略成“使用可用通道”。

不要求所有句子都短，也不设统一词数阈值。一个条件清晰的定理可以较长。若连续短句失去因果或对比关系，应恢复必要连接。能准确说明操作的专业术语可以保留，不必为了词汇多样而反复换同义词。

## 删除重复含义，保留不同阅读任务

同一段落若先报告一次结果，又用“换言之”重报一次，通常可以合并。没有新增信息的“这充分体现了重要价值”也不需要保留。结果段应解释比较回答了什么，而不是逐项朗读整张表。

摘要、独立图注和正文可能需要重复同一个分母或主要发现，因为读者会分别阅读这些部分。方法中的定义与结果中的应用也承担不同任务。以信息功能判断重复，不能仅靠词频或相同数字判断。

## 修改范围与验证

审查请求先给问题、位置、依据和保留项，不自动改写全文。明确要求修改时，完成范围内的修复，并核对数值、引文、否定、条件和结论强度。已通顺且有科学作用的句子可以原样保留。

若同时撰写 response letter 与正文，回复说明问题如何处理，正文直接解释研究。材料未提供某项分析，不等于研究没有做过该分析。待确认事项留在作者核对项中，不能为了让文字完整而补成研究事实。

## 可复制的请求

```text
使用 $academic-prose-editing 审查并修改所附段落。
先核对逻辑、证据、术语含义和自然搭配，再简化复杂句并删去同义重复。
检查论证是否逐步展开，句间和段间是否真正承接，表达变化是否服务于重点。
保留有用的平行结构，不虚构作者思考经历，不按固定句长制造变化。
不用解释性冒号或句中破折号，使用连贯段落。
保留术语内部的连字符、技术符号和原文引文。
保留必要条件、限制和已有的论证桥梁，不提高结论强度。
说明真正需要的修改，并标明可以原样保留的内容。
```

整篇文章的泛泛背景、失焦动机和章节脱节，需要先恢复研究主线，再进行句子编辑。见[论文结构与写作指南](manuscript-guide.md)。
