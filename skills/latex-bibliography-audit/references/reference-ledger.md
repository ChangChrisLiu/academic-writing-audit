# Reusable reference ledger

Use one task-local ledger across authenticity and format checks. A table or JSON is sufficient; no particular software is required. Keep original entries and occurrence locations, stable reference IDs, candidate duplicate groups, intended work/version, observed identifiers, per-field provenance, the two independent verification records, unresolved conflicts, and current status. Keep large source evidence separate and link it.

Candidate grouping is reversible indexing, not a verified merge. Each verifier receives the same original entries and candidate groups without another verifier's verdict or source selection. A repeated identical entry can share one source retrieval within each verifier's pass, but every variant's supplied fields and every occurrence must remain accounted for. Similar titles or DOI strings alone do not settle identity.

Reuse completed evidence when the work/version and relevant bibliographic fields are unchanged, the source record is traceable, its Incognito/Private mode is confirmed, and no new conflict or publication-status concern has appeared. A local citation-key rename or citation-style change alone does not require two new searches. Changed identity fields, a different intended version, or conflicting new evidence reopen the affected checks. Keep older captures with unknown or ordinary browser mode as historical evidence. Reopen their retrieval to meet the current mode requirement without rewriting their original records. Do not restart unaffected entries or treat a cached report as newly retrieved evidence.

## Browser mode for every retrieval agent

Use a confirmed **Incognito/Private browser context** for online literature searches, publication checks and Cite → BibTeX retrieval. Confirm the mode before navigation using an observed browser indicator or explicit tool metadata, and retain that evidence with the agent's record. A new tab, named session, separate profile or absent login does not by itself establish private mode. Each verifier must make its own retrieval and retain its own record. Browser mode does not establish agent independence or bibliographic truth.

Record the agent, browser/context identifier where safe, observed mode, mode evidence and inspection time. Keep source artifacts separate from private account information. Do not use the user's ordinary logged-in browsing session or sign into their accounts for this workflow. If the tool cannot create, control or confirm private mode, stop online retrieval and report the mode requirement incomplete. Continue permitted local checks with their own status. Never silently fall back to an ordinary window or an unconfirmed retrieval route. Access challenges still require stopping.

## Export and verification evidence

For every BibTeX entry, bind the intended work/version and its citation locations to the untouched Google Scholar Cite → BibTeX capture, its observed source, capture date, exported key and digest. Track confirmed private mode, export obtained, identity verified by both agents, and working entry exact or verified with a title-symbol normalization as separate outcomes. Record a missing capture, exact difference or source conflict per item. Place extra DOI values, local identifiers and publisher-only fields in this ledger. Google Scholar's actual Cite → BibTeX output supplies the bibliographic record. Preserve the full exported entry, including its key, subject only to the title-symbol exception below, and accept it only after the evidence checks pass. Keep an existing unresolved entry recoverable and leave any new entry pending until an actual export can be used. This gate also applies when BibTeX is used to populate another format.

A limited exception permits restoring special symbols or mathematical notation within the `title` value when the intended paper's displayed title confirms the same name and meaning. For example, a flattened `pi0.5` may be rendered with the Greek letter and the original subscript, using valid LaTeX or Word notation. Verify the actual typography instead of guessing it from the flattened string. Keep title words, numbers, version and meaning unchanged. Do not apply global replacements to ordinary words, abbreviations or technical terms. Preserve the raw Scholar capture and record the exact before/after title, supporting source and reason. All bytes outside the title value, including key, authors, year, venue and other fields, must still match the export. A title match alone does not establish publication identity.

Report this exception as **title-symbol normalization verified**, separately from an exact export match. Check the diff to ensure it changes only the intended symbol representation and any necessary protection within the title value. The local equality checker will report a difference for such an entry. Reconcile that difference with the documented title change and verify all remaining bytes, without altering the capture or claiming the checker returned an exact match. Keep uncertain notation pending. Inspect the rendered title when build or document rendering is in scope.

After reconciliation, format skills consume the ledger and preserve its source links. A blocked Scholar/export step stays blocked while independently supported metadata and completed local mapping checks keep their own statuses. Update the ledger after authorized repairs and invalidate any finding tied to superseded inputs.

If claim support is requested, attach the exact citing proposition and the source passage/result supporting or limiting it. Track that judgment separately from existence and formatting. Otherwise state that claim support was outside scope. Lead the user-facing report with consequential exceptions and a compact coverage summary; retain the detailed ledger as supporting evidence rather than repeating it in every stage.
