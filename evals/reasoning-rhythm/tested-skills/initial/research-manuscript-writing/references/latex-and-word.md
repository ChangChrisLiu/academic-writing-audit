# LaTeX and Word delivery

Use the same research argument in either medium. Document syntax serves the argument; it should not determine the literature categories or turn the paper into a list.

## LaTeX

Preserve the existing class, packages, macros, heading depth, bibliography system, citation keys, labels, and cross-reference convention. Use the template's section and subsection commands, not manually bolded mini-headings or Markdown. Follow its citation commands rather than choosing between `\citep`, `\citet`, `\cite`, and `\autocite` without knowing what is supported.

Keep math delimiters and environments balanced. Escape text characters such as `%`, `&`, `_`, and `#` where needed without corrupting math, URLs, or commands. Keep units, notation, quotation text, and identifiers intact. The preference against explanatory colons and interrupting dashes does not authorize changing ratios, label keys, negative signs, ranges, or template syntax. Do not use `itemize` to replace an argument that should be a paragraph.

For an excerpt, return only the requested source fragment. For an authorized file edit, preserve the project and check the diff. If compilation and render inspection are in scope and available, inspect the intended build and relevant pages. Otherwise report source-only checks and the missing dependency. Do not call a syntactically plausible fragment a successfully compiled manuscript.

## Word

For paste-ready prose, use plain headings and paragraphs with the supplied citation style, without Markdown heading marks, literal asterisks, or LaTeX commands. When identifiers are the only reference information supplied, use a clearly marked provisional citation convention outside the prose; do not fabricate authors or dates.

For an actual `.docx`, use native paragraph and heading styles, editable equations when needed, captions, and cross-reference or citation fields supported by the author's workflow. Preserve existing citation-manager fields, bookmarks, comments, and tracked changes unless changing them is requested. Do not flatten fields into text or replace document XML indiscriminately just to polish a sentence. If the available tool cannot preserve an existing feature, provide a bounded text proposal and state that limitation.

Check heading hierarchy, paragraph boundaries, tables, equation text, references, and the absence of conversion debris. Inspect the rendered document when tools and scope permit. A file that opens as a ZIP or contains valid XML is not proof of correct Word layout. Plain-text delivery is not a created or validated `.docx`.

## Citation and section consistency

Place a citation close to the proposition it supports, preserve author-approved quotation text, and keep bibliography entries aligned with supplied sources. Check that references survive a conversion and that method names and units remain stable. Use substantive headings for long literature threads when useful, without constructing a taxonomy or inserting mini-headings before every paragraph. Author and publisher requirements override the library's default presentation preferences.
