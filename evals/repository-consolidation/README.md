# Repository consolidation

This record covers the v0.9.0 reorganization of documentation, skill entrypoints and maintenance tools. The 18 skill names, independent installation contract, detailed research and citation workflows, and historical evidence remain available.

The landing pages now route to a [guide and skill catalog](../../docs/README.md) and a complete [evaluation index](../index.md). Drafting, argument repair and broad audit have shorter, distinct entrypoints. General prose instructions have one maintained [source](../../shared/prose-policy.md), bundled locally in 13 skills; the reference ledger likewise has one maintained source and three local copies. This intentionally retains packaging copies so an individual skill has no repository or sibling dependency. The prose source preserves every sentence of the former repeated policy, with only headings and paragraph boundaries changed.

Three fresh-context participants used complete standalone skill copies and five existing fictional packets, with no prior outputs or rubric. See the full [research](runs/research.md), [response](runs/response.md), and [specialist prose](runs/prose.md) answers, [fixed rubric](rubric.md), [input freeze](design-freeze.json), [separate assessment](independent-assessment.md), and [run metadata](run-metadata.json). These are regressions on known development cases, not held-out tests or a comparison proving the refactor improved writing. The separate assessor found no material scientific or prose failure.

One reused request describes a coordinator-managed pair. The current regression had one research participant, alongside separate response and prose participants. The research answer repeats that logistical phrase. The assessment and metadata retain this mismatch; no paired investigation or reciprocal research review occurred in this regression. The old case and new answer remain unchanged, and this is not treated as evidence of completed independent verification.

The [structural record](structural-checks.json) documents size changes, preserved policy text, historical-byte comparison and script tests. The original evaluation artifacts are unchanged; only the constructive-inquiry manifest's resolution metadata was pinned to its original version, with its expected hashes retained. The [manifest](manifest.json) binds this record and the released skill and maintenance files.

The portable tools check links, supported metadata, standalone dependencies, historical hashes and shared-copy equality. Twenty-three executable tests exercise meaningful validator and package failures in temporary repositories. An initial packaging test exposed missing regular-file mode metadata in Git ZIP entries; the implementation now reads authoritative modes from the Git tree and the complete test suite passes. Packaging verifies committed bytes and modes, refuses an existing output directory and does not publish.

These checks do not rerun Scholar retrieval, LaTeX rendering or native Word refresh, establish full research-team behavior, or prove general writing quality. The Word workflow and its ledger bytes were unchanged. Directory isolation and restricted reads were requested in prompts, not enforced by filesystem permissions. No private manuscript was accessed or edited.
